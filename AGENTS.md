# Repository Invariants

- **Deployment & Neon targets:** GitHub `main` auto-deploys to Vercel project `perks-reminder` (`prj_x0VAgiuO3PAem4IUmeVo9dsRMCsx`, distinct from the `perks-reminder-sandbox` project linked in local `.vercel/project.json`) without running Prisma migrations (`docs/vercel-domains-and-deploy.md`, `docs/supabase-fallback.md`). Never merge schema-dependent request paths before `npm run db:prod:migrate`, and never run `prisma migrate reset` or `--force-reset` against Neon (`DATABASE_URL` pooler, `DIRECT_URL` direct, `DATABASE_URL_DEV` dev).
- **Cron & email boundaries:** `vercel.json` schedules `/api/cron/check-benefits` (`0 5 * * *`) and `/api/cron/send-notifications` (`30 5 * * *`, `maxDuration = 10`) authenticated by `Bearer <CRON_SECRET>`; never trigger production notification routes during testing (`mockDate` still sends Resend emails).
- **Public DB-free surface:** Anonymous catalog, usage-guide, and search routes must stay free of top-level Prisma/auth imports (`npm run check:public-db`).
- **Catalog & card identity:** Every `PredefinedCard` and `PredefinedBenefit` carries an immutable `catalogKey` in `src/lib/static-catalog.ts` (`npm run card-template:validate`); physical cards remain distinct by `CreditCard.id`.
- **Amex reader editions:** Chrome extension (`release/chrome-extension`, Web Store item `idpcieaeladegdoelljadhcggjndclpk`) and Tampermonkey userscript (`release/perks-reminder-amex-reader.user.js`, Greasy Fork `591349`) share `src/lib/amex-benefit-reader/`. WXT local dev binds `127.0.0.1:8731` (`docs/reader-development.md`); enable only one reader edition at a time and preserve existing storage/profiles.
- **Catalog freshness & card art:** Encode timed offers and scheduled issuer changes as `sunsetAfter` / `upcomingChanges` / `openDrift` metadata (never prose); `npm run catalog:freshness` (add `--fetch` to diff issuer pages into `build/catalog-freshness/`) must report 0 errors. All card art is generated by `npm run card-art:generate` (a test rejects non-generated manifest entries); never commit issuer artwork.
- **App E2E:** `npm run build && npm run test:e2e:app` runs `playwright.app.config.ts` against `next start` on the dev database with `RESEND_API_KEY` cleared and seeds the E2E user via `scripts/e2e-seed-user.ts` (dev-only guard).
